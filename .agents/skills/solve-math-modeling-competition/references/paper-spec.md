# 中文数学建模论文规范

## 目录结构

保持论文模块化：

```text
论文/
├── 论文.tex
├── format.cls
├── fonts/
├── 0.摘要.tex
├── 1.引言.tex
├── 2.总体分析.tex
├── 3.模型假设.tex
├── 4.符号说明.tex
├── 5.模型的建立与求解.tex
├── 5.1.问题1的建立求解.tex
├── 5.1.1.分析与准备.tex
├── 5.1.2.建模与求解.tex
├── 6.模型检验.tex
├── 7.模型评价.tex
├── 8.模型改进推广.tex
├── 9.参考文献.tex
└── 10.附录.tex
```

根据问题数量生成 `5.X`、`5.X.1`、`5.X.2`。总结建议类问题可以不机械拆分。除目录后的自然分页外，不人为插入 `\newpage`。

## 通用要求

- 只在 TeX 文件中保留可编译内容，删除所有占位符和提示语。
- 正文以自然段为主；步骤或假设确需枚举时使用一致的结构。
- 避免无意义加粗。摘要中的问题标签、问题重述和步骤标题可使用 `\textbf{}`。
- 每个图表都在正文首次出现前后被明确引用。
- 图题、表题、坐标轴、图例与正文使用中文，单位和有效数字一致。
- 不为满足篇幅机械堆公式、图或表。所有内容都必须服务于论证并可追溯到结果。
- 赛题官方格式要求高于本模板。

## 主文件

模板的主文件应包含 `ctex`、`longtable`、`booktabs`、`array`、`tikz` 等实际用到的宏包，并按章节顺序 `\input{}`。不要同时加载互相冲突或完全未使用的宏包。

编译前核对每个 `\input{}`、图片路径、label 和 citation 是否存在。论文从 `论文/` 目录编译，因此图片通常通过 `../求解/问题X/图片/文件名.png` 引用。

## 摘要

摘要通常不超过 900 个中文字符并控制为一页，但若赛题规定不同则遵守赛题。

组织为：研究对象与统一主线 → 逐问任务、模型、算法和关键定量结果 → 必要的结论边界 → 3–6 个关键词。每问通常使用 2–3 个职责清楚的短句：第一句交代任务或难点，第二句说明模型与求解思路，第三句报告最重要的数值结果及其性质；简单问题可以合并，但不得把多个模型、算法和结果压入一个难以解析的长句。

摘要完成后逐句标注其主要功能：`任务 / 模型 / 算法 / 结果 / 评价或边界`。检查以下问题：

- 每问是否出现可辨认的模型或数学结构，而不只出现算法名；
- 每问是否给出至少一个关键数值或可核查结论；
- “最优、显著、稳定、有效、普适”等词是否有正文证据及适用范围；
- 是否删除“性能优越、结论可靠、提供理论依据”等无信息量套话；
- 未阅读全文的读者能否仅凭摘要复述四问分别做了什么、怎么做和得到什么。

只有 `求解/创新性审查报告.md` 中“已验证”的项目才能在摘要中作为创新或改进强调；不要在摘要中放公式、图表或引用。

编译后通过 PDF 页图或辅助标签检查摘要实际页数，不要仅按字符数推断。

## 引言与总体分析

引言依次说明背景、问题来源、现实或研究意义，再用简洁语言重述每问。引用真实且相关的领域资料。若论文主张创新，必须介绍最近方法的相关做法、尚存限制和本文实质差异，不能只用“现有研究不足”概括。

总体分析说明各问之间的递进或数据依赖，概述每问为何采用对应方法。不要提前泄漏未经展示的结果，也不要重复题面。

## 模型假设与符号

每条假设都应必要、可解释，并说明其适用边界。不要把事实、定义或求解结果写成假设。

符号表只收录正文实际使用的重要符号，并统一含义、量纲、上下标和集合记号。同一符号不得在不同章节表示不同含义。

## 表格

跨页表优先使用 `longtable`。表格宽度必须在 `\textwidth` 内；不要要求所有单元格强制单行，因为长文本在窄列中应合理换行。

典型结构：

```latex
\begin{longtable}{>{\centering\arraybackslash}p{0.18\textwidth}>{\centering\arraybackslash}p{0.76\textwidth}}
  \caption{表名}\label{tab:label} \\
  \toprule
  列1 & 列2 \\
  \midrule
  \endfirsthead
  \caption{表名（续）} \\
  \toprule
  列1 & 列2 \\
  \midrule
  \endhead
  \bottomrule
  \endfoot
  内容 & 内容 \\
\end{longtable}
```

根据字号、`\tabcolsep` 和实际文本计算列宽；不要依赖固定的“列数—比例总和”公式。编译后检查 overfull box 和可读性。

## 每问的分析与准备

先说明问题类型、输入、输出和难点，再给出完整求解链路。流程图仅在它能澄清多阶段关系时使用；框数、布局和方向根据实际流程调整，不强制固定九框。

本问分析应说明“为何建立这个模型”，而不是只列出随后将运行的程序。至少回答：直接求解为什么困难、题目中的哪些结构可以利用、哪些离散与连续因素需要分离、哪些目标具有主次关系、哪些假设使模型可计算。若四问存在递进关系，说明前问输出如何成为后问输入或约束。

问题一通常包含数据理解和预处理。报告清洗前后的样本数、缺失处理、异常值策略、单位变换、标准化或特征构造，并给出采用这些处理的理由。

预测、分类和启发式优化的算法选择通常至少比较一个简单参照和主要候选，从准确性、可解释性、约束处理、稳定性、计算成本等与问题相关的维度选择。严格解析、枚举、证明或题面唯一指定的模型可以不安排形式化算法竞赛，但必须解释适用性。比较结论需要实验、理论性质或可靠文献依据；不要使用没有证据来源的“优、良、中”主观等级表。

## 模型建立与求解

模型建立与算法求解是相互对应但不同的内容。模型回答“数学上决定什么并满足什么条件”，算法回答“如何计算这个模型”。正文不得直接从问题分析跳到代码流程。

模型建立必须明确：

- 决策变量、状态变量、参数、集合和单位；
- 目标函数或统计学习目标；
- 约束、边界条件或数据生成假设；
- 求解算法和关键参数；
- 输出如何映射回题目要求。

公式从问题逻辑自然推导，公式之间用文字解释。不要为达到公式数量而拆分恒等变换。每个新符号在首次出现时解释，程序实现与公式保持一致。

对于优化模型，优先使用可辨认的语义模块：

1. 集合、参数与单位；
2. 决策变量或状态变量；
3. 目标函数及各项含义；
4. 约束条件及其现实来源；
5. 模型性质、建模动机与适用边界。

统计学习、机理和评价模型可将这些标题替换为相应的学习目标、数据生成假设、状态方程、边界条件、指标体系等，不机械套用优化模型标题。

每个核心算法至少回答：输入是什么、输出是什么、初始状态如何获得、每轮如何更新、如何维持或恢复可行性、何时停止。复杂多阶段算法应使用编号步骤、紧凑伪代码或能表达数学关系的流程图之一；流程图应展示模型状态与决策关系，不能只画“读取数据—调用程序—保存结果”。源码附录不能替代正文原理说明。

模型求解按“输入与参数 → 算法原理与步骤 → 关键设置与停止条件 → 结果表/图 → 定量分析 → 小结”展开。运行环境只有在影响数值差异、复现要求或赛题明确要求时才放入正文，否则移至附录或支撑材料。明确区分观测数据、模型估计、预测和情景模拟。创新方法还要说明其针对的基线局限、作用机制、最近方法差异和最小消融设计，避免把通用模型介绍当作创新说明。

主要结果段遵循“数值—现象—原因—意义”：先报告明确结果，再描述跨数据或跨情景现象；原因分析区分程序复算、消融或理论支持的解释与尚未验证的合理推测；最后说明结果验证了哪项模型设计或回答了哪个题目要求。不要把三组算例表现直接外推为普遍规律。

## 模型检验

按问题类型选择检验：

- 预测：时间切分或交叉验证、残差、基线和多指标；
- 分类：混淆矩阵、精确率/召回率/F1、ROC-AUC 或 PR-AUC；
- 优化：可行性、约束违反、上下界、多初值稳定性；
- 评价：一致性、权重扰动和排序稳定性；
- 机理：量纲、边界、参数敏感性和外部数据对照。

灵敏度分析改变最关键且有解释意义的输入或参数。报告扰动范围、评价指标、结果变化和结论是否稳健。

创新检验必须引用 `创新实验矩阵.csv` 和对应结果文件，至少展示稳定基线、创新完整模型和关键组件消融。若提升未超过实验波动，或机制消融不支持创新假设，缩小或删除创新表述。交互、协同或因果性结论需要置信区间、置换检验、留出增益或同等级证据。

## 模型评价与推广

优缺点必须针对实际模型与验证证据，不使用通用套话。单独区分经消融支持的创新、工程适配和流程贡献；“部分验证”必须带限定条件，“未验证”或“失败”只能写入限制与改进方向。说明数据限制、假设边界、计算复杂度、泛化风险和可改进方向。推广部分明确哪些结论可迁移、需要哪些新数据和需要重新估计哪些参数。

## 参考文献

使用赛题要求的引用格式；无明确要求时可采用 GB/T 7714—2015。通常保留 8–15 条高相关来源，但质量优先于数量。

- 核验作者、题名、期刊或出版社、年份、卷期页码和可访问链接/标识符。
- 正文每个 `\cite{}` 都必须存在对应条目，每条参考文献也必须在正文被引用。
- 优先引用算法原始论文、权威教材、官方数据和领域研究。
- 不把 Python 包名或虚构论文当作方法论引用；软件需要引用时使用其官方推荐格式。

## 编译与逐页检查

至少运行两遍 XeLaTeX。检查退出码和日志中的：

- `Error`、`Undefined control sequence`、缺失文件；
- `Overfull`、`Underfull`、`Float too large`；
- 字体缺字、未定义引用和未定义 citation。

将 PDF 渲染为页面图像，逐页确认封面、摘要、目录、页码、公式、长表、图片、参考文献与附录。修正内容或布局后重新编译和复查。

在最终交稿前再执行一次独立的“五分钟评委盲审”。只查看摘要、目录、各问首段、主要公式、核心图表和结论，检查能否快速回答：

- 每问需要解决什么，真正难点是什么；
- 为什么建立该模型，变量、目标和主要约束是什么；
- 算法为何适用于该模型，核心步骤与停止条件是什么；
- 最关键的数值结果是什么，哪些是严格结论，哪些只是启发式可行结果；
- 四问之间是否存在清楚的统一主线。

若任何核心信息必须阅读源代码或搜索多页才能确定，应返回摘要或相应章节修改。版面无错误不等于内容已经通过验收。
